# Records and read-model projections

Reported 2026-10-25. Status: partial answers; pending retest.

Java record gap: record components are final references and accessors are `name()`, `tags()`, not JavaBean getters generated by default. `record Task(String name, List<String> tags)` is only shallowly immutable. A caller can mutate the original mutable list after construction or mutate the list returned by `task.tags()`. Defensive copy in constructor (e.g. `this.tags = List.copyOf(tags)` using an appropriate constructor form) prevents changes to the collection; deeper mutable elements require separate protection. Retest with a tiny example.

JPA gap: if an endpoint needs only project ID and task count, return a projection/DTO via aggregate query, e.g. LEFT JOIN tasks, COUNT(t.id), GROUP BY p.id. Fetch join loads tasks and is usually the wrong shape for count-only output; native SQL is not required, JPQL can express this. Verify generated SQL and pagination/cardinality. Retest query shape and zero-task projects.
