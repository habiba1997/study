# Records and read-model projections

Reported 2026-10-25; assessment corrected 2026-10-27. Pending independent retest.

Java record gap: record components are final references and accessors are name(), tags(), not JavaBean getters generated by default. A record containing List<String> is only shallowly immutable unless defensively copied. Caller can mutate a mutable original list or returned list. List.copyOf in an appropriate constructor prevents list structure changes; mutable elements require separate protection.

Assessment correction: Habiba clarified she intended a native SQL query returning only project ID and task count as a projection. This is a valid solution. Do not record fetching full entities or fetch-join misuse as her mistake. The coach had misinterpreted the answer.

General learning note: LEFT JOIN tasks, COUNT(t.id), GROUP BY p.id can include zero-task projects. Native SQL or JPQL can express the aggregate; native SQL is not automatically faster just because it is native. Verify actual SQL, query plan, pagination and cardinality. Fetching all tasks is unnecessary for count-only output.

Retest: explain record list mutation; design aggregate query including projects with no tasks. Do not infer mastery from the explanation.
